# Godot MCP Instructions

## Priority Directive for AI Coding Assistants

When working on this Godot project, **always use the Godot MCP server tools** as the primary interface for interacting with the project. This ensures real-time synchronization with the editor and proper scene management.

### When to Use Godot MCP

- **Scene Manipulation**: Use `mcp_godot-mcp_open_scene`, `mcp_godot-mcp_create_scene`, `mcp_godot-mcp_save_scene`
- **Node Operations**: Use `mcp_godot-mcp_create_node`, `mcp_godot-mcp_delete_node`, `mcp_godot-mcp_update_node_property`, `mcp_godot-mcp_get_node_properties`
- **Script Management**: Use `mcp_godot-mcp_create_script`, `mcp_godot-mcp_read_script`, `mcp_godot-mcp_modify_script`
- **Scene Tree Navigation**: Use `mcp_godot-mcp_get_scene_tree`, `mcp_godot-mcp_list_nodes`
- **Editor State Queries**: Use `mcp_godot-mcp_get_editor_state`, `mcp_godot-mcp_get_current_scene`
- **Project Execution**: Use `mcp_godot-mcp_run_project`, `mcp_godot-mcp_stop_project`

### When to Avoid File Editing Tools

Do **NOT** use generic file editing tools like `read_file`, `replace_string_in_file`, or `create_file` for `.tscn` (scene) or `.gd` (script) files when working with this Godot project. Always defer to the corresponding MCP tools instead.

### Why?

1. **Real-time Sync**: MCP tools ensure changes are immediately reflected in the Godot editor
2. **Validation**: MCP tools validate Godot-specific properties and constraints
3. **Consistency**: Using MCP prevents out-of-sync state between the file system and the editor
4. **Efficiency**: MCP tools provide direct access to node properties, reducing manual parsing

### Example Pattern

**❌ Avoid:**
```
Use read_file to check scene structure
Manually edit offsets in test-scene.tscn
```

**✅ Use:**
```
mcp_godot-mcp_get_scene_tree to inspect structure
mcp_godot-mcp_update_node_property to modify node positions
```
